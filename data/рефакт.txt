Контекст проекта: Интернет-радио на одноядерной плате Lolin/Wemos S2 Mini (ESP32-S2).
Используемые библиотеки: SettingsGyver + GyverDBFile (база данных) для веб-интерфейса, PubSubClient для MQTT (интеграция с Home Assistant по топику yoradio/homeradio), Adafruit_SSD1306 для OLED, и внешняя микросхема VS1053 (библиотека ESP32-vs1053_ext, объект `VS1053 *player`).

Текущая архитектура и связи:
1. База данных и ключи объявлены в web_server_module.cpp: объект `GyverDBFile db(&LittleFS, "/db.bin");`, сервер `SettingsGyver sett("ESP32-S2 Radio", &db);` и макрос `DB_KEYS(kk, vol, bass, treble, st_id, c_url, txt_st, txt_tr, sys_log);`.
2. В main.cpp база объявлена через `extern GyverDBFile db;`. Для чтения ключа без дублирования kk используется официальный метод `db.has(SH("st_id"))` и `db[SH("st_id")].toInt()`.
3. Массив станций объявлен в main.cpp как `Station stationList[MAX_STATIONS]; int stationCount = 0;` на основе структуры из config.h (`extern Station stationList[]; extern int stationCount;`).
4. Файл плейлиста /stations.txt парсится по знаку табуляции '\t'. Из него автоматически генерируется файл /ha_playlist.txt (разделитель '\t') для Home Assistant.

Что сделано в текущей сессии:
1. Написан и интегрирован модуль диагностики system_logger.h на базе официального класса `sets::Logger webLogger(256)`. Лог дублируется в Serial, буфер и файл /log.txt. Добавлен замер пинга до шлюза и проверка доступности хоста сокета `checkUrlAvailability`.
2. Реализовано автоматическое сохранение индекса последней станции во Flash при переключении кнопками Назад/Вперед (через db[kk::st_id] = currentStationIdx; db.update();) и автозапуск потока при старте в setup().
3. Исправлен виджет b.Select в веб-сервере (заменен разделитель элементов на точку с запятой ';').
4. Найдена причина краша OTA на 60% (одноядерный процессор S2 захлебывается из-за наложения бинарного потока прошивки, фоновых AJAX-запросов updateInterface веб-страницы и прерываний loopAudio).
